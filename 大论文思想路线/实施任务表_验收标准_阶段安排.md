## −1. v3 的优先级原则（与 v2 最大的差别）

v2 按**依赖顺序**排任务（先修数据链，再做模块，最后实验）。v3 改为**先立创新点，再补完善度**，理由：

- 两项 **★I（首创性）**——仰角盲区角、阴影可反演性包线——**验证成本极低**（一个解析脚本 + 改 config 跑几组），却决定全文主线是否成立。必须最先做。
- 三项 **★II（改进性）** 的成立条件是"指名基线 + 同条件可比 + 量化改进 + 诚实边界"（详见 `创新点内容设计_定稿.md` §1.0 的 C1–C4）。**基线不复现，主张即作废**，因此 `baseline_aykin_carve.py` 与 `baseline_zhou_shadow.py` 的优先级等同于主体开发，不能排到最后。
- 自家模块的完善（白化、向量化、语义因子等）都是 ○ 项，缺了会被问，但不决定创新点存亡，可后置。

**一句话**：**别人做过不等于我们没有创新空间**，但"做得更好"必须以复现别人的方法为前提——这是 v3 把基线任务前移的唯一理由。
