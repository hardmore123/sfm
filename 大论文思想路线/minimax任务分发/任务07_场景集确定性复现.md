# 任务07 · 场景集确定性复现（安全，零副作用）

## 目标

验证唯一有效场景集 `scene_set_main_f8` 能由固定种子**确定性重生成**：把生成器输出改到
**临时目录**再生成一份，与交付副本逐文件比对。这既核验"数据可复现"这一交付承诺，
也保证交付数据没有被悄悄改过。

> ⚠️ 安全说明：本任务用的执行器 `repro_scene_check.py` 已把生成输出重定向到临时目录
> `F:\sfm\_repro_check\`，**绝不覆盖**交付数据 `04_数据\scene_set_main_f8`。
> **不要**直接运行 `gen_scenes_main_f8.py`（它会原地覆盖交付数据）。

## 怎么做（一条命令）

```powershell
cd F:\sfm\论文代码与数据\02_代码
python _setup_data.py            # 首次执行前跑一次
cd F:\sfm\大论文思想路线\minimax任务分发\工具
$env:PYTHONIOENCODING = "utf-8"
python repro_scene_check.py       # 约 8–10 分钟（含重新生成 5 个场景）
```

产物：`回报\日志\repro_scene_check.log`（退出码预期 `0`）

跑完后删临时目录（可选，释放约 469 MB）：

```powershell
Remove-Item -LiteralPath F:\sfm\_repro_check -Recurse -Force
```

## 已知基线（正确答案）

Kiro 已实测（2026-09-09 重建后）：**60 个文件全部逐字节一致**（55 个 `.npy` + 5 个 `meta.json`）。
若再次运行，`meta.json` 可能仅 `timing_s`（运行耗时）不同，属实质一致。

| 项 | 期望 |
|---|---|
| 交付/复现文件数 | 各 61 |
| 逐字节一致 | 55–60（.npy 必须 55 个全一致） |
| meta 仅 timing 差（实质一致） | 0–5 |
| 实质不一致 | **0** |
| 仅交付有 / 仅复现有 | 0 / 0 |
| 结论 | "确定性可复现 ✅" |

## 验收标准（客观）

- **V1**：报告显示"实质不一致：**0**"且"仅交付有 0 / 仅复现有 0"，退出码 0。
- **V2**：结论为"确定性可复现 ✅"。

两条满足 ⇒ 任务07 **通过**。若"实质不一致 > 0" ⇒ **未通过**，把不一致文件清单抄进回报
（意味着要么生成非确定性、要么交付数据被改过，需 Kiro 排查）。
