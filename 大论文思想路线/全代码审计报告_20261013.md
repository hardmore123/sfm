## 三、严重问题详解（★★★，必须修正）

### 问题1：closed_loop_theory.py — joint_carve_with_height 必然崩溃（★★★）

**位置**：`closed_loop_theory.py:187`

```python
alive = voxel_carve(poses_se3, form_masks, voxel_centers, ...)
# voxel_carve返回(alive, alive_hist)二元组，alive是tuple不是数组
delete_mask = mask_target & mask_height & alive  # 对tuple做布尔运算→ValueError
```

**为何测试"通过"**：`test_step8_joint`不调用`joint_carve_with_height`，而是手动重抄逻辑跑在`alive=np.ones(...)`上。崩溃路径被测试系统性绕开。

**性质**：代码声称实现了"步骤8联合雕刻"，但实际是**不可执行的死代码**。

### 问题2：closed_loop_theory.py — kappa_to_s 默认阈值矛盾（★★★）

**位置**：`closed_loop_theory.py:126`

默认`thresholds=(0.05, 1.0)`意味着κ≥1.0才算良约束。但T2判据说κ=λ₃/λ₂>0.05即良约束。κ=0.15（远超0.05）被误判为弱约束(s=0.5)。

ARIS几何下λ₃/λ₂理论上限≈sin²(7.5°)=0.017，现实中0.05~0.18的良约束值全被压成0.5。

**为何测试"通过"**：测试显式传`thresholds=(0.01, 0.05)`绕开了默认值，默认路径从未被覆盖。

### 问题3：closed_loop_theory.py — σ_e公式与理论文档不一致（★★★）

**位置**：代码`closed_loop_theory.py:65-87` vs 文档`理论修正_T1-T6.md:338`

代码的微积分正确（数值有限差分验证吻合到1e-10），但**理论文档公式漏了一个cos(e)因子**。论文若引用文档公式会得到偏大~12%的σ_e。

**按D10纪律**：代码与文档冲突时应先改文档再改代码。当前文档错，代码对。

### 问题4：closed_loop_theory.py — poses_se3契约矛盾（★★★）

**位置**：`closed_loop_theory.py:172`（docstring说(K,6)）vs `R_x6_carve_fixed.py:52`（代码用(K,4,4)的[:3,:3]和[:3,3]）

调用者无论传哪种形状都可能出错。

### 问题5：ba_unified.py — sanity测试循环论证（★★★）

**位置**：`ba_unified.py:416-430`

```python
target = ba.elev0[test_ids] + 0.10  # 先验=初值+常数
elev_before = ba.elev0[test_ids]    # "基线"=初值
pull0 = mean(|elev_before - target|)  # ≡0.10(常数)
# 判定: pull < pull0*0.6 → 先验起效
```

先验target由初值+0.10构造，pull0≡0.10是常数而非独立无先验基线。这是自我实现的预言——只证明了"加强先验能把解拉向先验本身"这一平凡事实，不能证明先验注入通道对外部真先验有效。

### 问题6：terminal_evaluation.py — floating_point_density 自指（★★★）

**位置**：`terminal_evaluation.py:84-92`

```python
thr = np.quantile(densities, 0.02)
return float(np.mean(densities < thr))  # ≡0.02(恒等于分位数定义)
```

`np.quantile(d, 0.02)`保证恰好有2%样本小于该分位数，返回值恒≈0.02，无论重建质量如何。这是**自指定义**——指标值被硬编码在定义里，不随重建质量变化。论文若以此声称"漂浮点占比低至2%"是误导。

### 问题7：terminal_evaluation.py — voxel_error 空集返回E=0（★★★）

**位置**：`terminal_evaluation.py:105-108`

```python
if union == 0:
    return 0.0, 0, 0, 0  # 空集=完美(E=0)!
```

两个空集之间的"完美匹配"是荒谬的。一个完全不输出的重建得到E=0（满分）而非E=1或报错——**反向激励漏洞**。

### 问题8：gen_scenes_main_f8.py — D_far用GT构成循环（★★★）

**位置**：`gen_scenes_main_f8.py:209, 219-221, 234-239`

```python
P_top = np.array([D_T, 0.0, h])  # D_T=10.6=GT水平距
# 用P_top[0]=D_T算D_far → 注入噪声 → 喂给反演
```

D_far的"BA输出"实际是从GT柱心坐标算出来的，注入σ_Dt=0.02噪声只是给真值加扰动。`meta.json`却声称`"leak_free": True`。**用GT当BA输出 → 反演误差自然很小 → 自我实现的预言**。

### 问题9：gen_scenes_main_f8.py — M5低SNR场景无效（★★★）

**位置**：`gen_scenes_main_f8.py:102-106`

```python
try:
    cfg.noise.speckle_sigma = speckle  # SensorNoiseCfg无此字段→AttributeError
    cfg.noise.noise_floor_db = noise_floor
except Exception:
    pass  # 静默吞掉
```

`speckle_sigma`和`noise_floor_db`属于`SonarCfg`而非`SensorNoiseCfg`，赋值必失败被`except: pass`吞掉。且`shadow_f8_fixed.render_all_fixed`根本不读这两个参数（纯二值掩码渲染）。

**后果**：M5声称"★II低SNR"但与M1几何完全相同，噪声参数从未生效。M1-M5在像素层面只有h和heave不同，阴影掩码都是无噪声理想二值图。

### 问题10：verify_rx5 — 常数D_far对比不公平（★★★）

**位置**：`verify_rx5_zhou_comparison.py:92-93`

```python
D_far = D_t + r_cyl  # 10.85, 全帧恒定
```

本文方法用常数D_far=10.85，但生成器对每根波束按方位偏移计算逐波束D_far(10.66~10.87)。常数D_far导致h系统性偏低，MAE从0.116cm→2.218cm（放大19倍）。而Zhou公式消去D_far自动免疫此误差。

**结论方向被颠倒**：报告显示Zhou比本文好8倍(ratio=0.123)，但用正确逐波束D_far后本文(0.116cm)优于Zhou(0.273cm)。

### 问题11：verify_rx5 — 成功率循环定义（★★★）

**位置**：`verify_rx5_zhou_comparison.py:122, 132`

`success_rate = n_our / n_valid`，其中n_valid="已量到阴影远端的列数"，n_our="其中反演出有限h的列数"。由于h>0&h<5很宽松，success_rate几乎恒=1.0。**分母已被筛成必然成功的子集**，工况2"本文100% vs Zhou 0%"两端都不可信。

### 问题12：verify_rx5 — Zhou单次通过硬编码0%（★★★）

**位置**：`verify_rx5_zhou_comparison.py:153`

```python
zhou_single_rate = 0.0  # 定义为0%成功率
```

没有任何代码实际尝试用单帧调用Zhou公式。"Zhou单次通过≈0%"是人为指定的常量，不是实验测出的结果。

**实事求是**：

1. **物理核心正确**：CRLB、阴影反演、σ_h传播、BA参数化、空间雕刻AND语义——这些是论文的理论基础，经审计**确认物理正确**。

4. **场景生成有GT泄漏**：D_far用GT柱心坐标算出却标leak_free=True，M5低SNR噪声参数从未生效。

5. **已修正2个★★★**：F-4b柱面先验(上轮)、G6人为设定(上轮)。剩余10个★★★待修正。

**下一步**：执行P0修正（10个★★★），重跑reproduce_all确认13/13，更新理论文档完成度。
